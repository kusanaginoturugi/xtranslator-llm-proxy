# 仕様

## 入力（xTranslator → proxy）

- `POST /v1/chat/completions`、OpenAI 互換 JSON
- 最初の `role: user` メッセージの `content` を使い、**1 行目をクエリとして捨て、2 行目以降を原文**とみなす
- それ以外のフィールド（`model`、`temperature` など）は無視する

`--dump` で確認した実際のリクエスト（2026-09-30、xTranslator / `Embarcadero RESTClient/1.0`）:

```json
{"model": "<OpenAI_Model>",
 "messages": [{"role": "user",
               "content": "<OpenAI_Query（%lang_dest% は展開済み、%lang_src% は未展開のまま）>\r\n<要素1>\r\n<要素2>"}]}
```

- 改行は `\r\n`。`OpenAI_ArrayLimit=2` のときは 2 要素が `\r\n` でつながって 1 リクエストになる
- system メッセージなし、`stream` なし。`Connection: Keep-Alive` を送ってくるが、`Connection: close` で返して問題ない
- `OpenAI_CharLimit` を超える要素は xTranslator 側で捨てられ、送られてこない
- プロキシは中では `\n` で扱い、応答は**受け取った改行コード（`\r\n`）に戻して**返す。行数は要素数と一致させる必要がある
- 要素の中に改行がある場合、要素の区切りと区別できない。行数さえ保てば xTranslator 側で正しく戻る前提（要確認）

## 翻訳の流れ

1. 辞書の元ファイル（スナップショット / local TSV）の mtime・サイズが変わっていれば辞書を作り直す
2. **全文一致**: 原文全体が翻訳メモリにあれば、それを返す（`glossary`）
3. **行単位一致**: 各行を翻訳メモリで引く。全行（空行以外）が解決したら、それを返す（`glossary`）
   - `Spell Tome: <呪文名>` は `呪文の書: <呪文名の訳>` に展開する
4. 未解決の行だけをまとめて LLM に回す（一部だけ解決した場合は `glossary+<model>`）
   - LLM 出力の行数が未解決の行数と合わなければ、部分合成をやめて全文を訳し直す
   - 長文の振り分け: `XTRANSLATOR_LONG_MODEL` を設定し、未解決テキストが `XTRANSLATOR_LONG_MIN_CHARS`（既定 1000、空白を除く）字以上なら、長文用の上流（`XTRANSLATOR_LONG_UPSTREAM` / `_LONG_API_KEY` / `_LONG_EXTRA_BODY`）へ送る
   - 長文用の上流が 200 以外・接続エラーを返したら（回数制限の 429 など）、ローカルのモデルで訳し直す。timeout のときは訳し直さない
5. **キャッシュ**: `prompt版数 + model + 未解決テキスト` をキーに保存・再利用する（`cache`）。問題が残った訳も保存する（「検証と再試行」参照）
   - 長文の振り分け先で見つからなければ、ローカルのモデルのキーでも探す（振り分けを入れる前の訳を使う）

## 翻訳メモリ・用語・例文（`lib/dictionary.rb`）

- 入力: local TSV → 辞書スナップショット（`dictionary.jsonl`）→ 作業中辞書（`session.jsonl`）の順。同じ原文は先勝ち
- スナップショットは書き出しツールが「ini の並び順の SST → ini にない SST（名前順）」の順で、原文ごとに先勝ちで書き出したもの
- **翻訳メモリ**: 全エントリ。完全一致 → 大文字小文字を無視した一致の順で引く
- **用語**: 旧 `usable_entry?` の基準（3〜80 文字、7 語以下、改行や `<>` を含まない、文末記号なし、全部小文字ではない）に加え、前後の空白や `()[]!?.;"…*` を含むもの（`(Laughing.)`、`No. ` のようなセリフ断片）を除く
  - 原文を単語に分けて、左から最長一致（最大 8 語）
  - 2 語以上の用語は、2 語目以降の大文字小文字が一致したときだけ採用する（`an Imperial sword` を `Imperial Sword = 帝国軍の剣` にしない）
  - 1 語の用語を採用するのは、原文で大文字始まり かつ 訳にカタカナを含むときだけ（`Speak = 話す` や、パーク名などのタイトルケースで `Your = あなたの` を拾わないため）
  - 2 語以上でも、原文側が全部小文字の句（`pick up`）は採用しない
  - 作業中辞書からは 2 語以上の用語だけ採用する（`Dragonbone = ドラゴンボーン` のような 1 語の誤訳を広めないため）
  - local TSV の用語は無条件で採用
- **類似例文**: 20〜300 文字で、訳に日本語を含むエントリ。原文と共有する単語の IDF 合計を、例文の語数の平方根で割ってスコアにし、上位 3 件を使う
  - 出現する例文が 400 件を超える単語は、ありふれていて手掛かりにならないので無視する

## 作業中辞書

- 検証で問題が出なかった LLM の訳を、未解決テキストと出力の行数が合うときに 1 行ずつ `session.jsonl` に追記し、その場でメモリ上の辞書にも足す（再構築はしない）
- 既に辞書にある原文、訳に日本語を含まないもの、原文と同じものは入れない
- 類似例文は、作業中辞書から最大 `SESSION_EXAMPLE_LIMIT` 件を優先し、残りを公式訳で埋める。並びは 公式訳 → 作業中辞書（原文の直前）
- スナップショットの SHA256 を `session.jsonl.snapshot` に記録する。辞書の再構築時にハッシュが前回と違えば `session.jsonl` を消す
- `session.jsonl` が外から消されたら、次のリクエストで辞書を作り直す

## プロンプト

TranslateGemma の公式プロンプトの形を土台に、次を足した 1 つの user メッセージにする。

- ルール（行数を保つ、`<mag>` などのプレースホルダを保持、名詞句は名詞句で訳す）
- `Glossary`: `原文 = 訳` の形で最大 40 件
- `Reference translations of similar lines`: 類似例文（公式訳と作業中辞書）を `English:` / `Japanese:` の対で最大 3 件
- 再試行時のみ: 前回の問題点

`temperature=0`、`max_tokens=原文文字数×3`（64〜8192 の範囲に収める）

## 後処理（旧実装から継承）

- コードフェンス、箇条書き・番号、太字、`Japanese:` のようなラベル、`=>` を含む行を削る
- 原文にない `<tag>` を削る
- 行数が違う場合、1 行の原文なら結合し、空行を除いて行数が合うならその形に揃える
- 原文の行末に `.` / `。` がないのに訳の行末に付いていたら削る

## 検証と再試行

次のどれかに当たったら、指摘をプロンプトに足して `XTRANSLATOR_RETRIES` 回まで再試行する。最終的には問題の少ない出力を採用する。

- 行数が原文と違う
- 原文のプレースホルダが欠けている
- 用語集の訳語が出力に含まれていない（空白・`・`・`=` は無視して比較）
- 原文が 3 語以上なのに、出力の半分以上が英字（未翻訳）。`<...>` と `[pagebreak]` などの `[...]` の中は数えない
- 出力に小文字始まりのラテン文字の単語が混ざっている（`wielderに`、`voluntadで`）。大文字始まりは固有名詞として許す

再試行は、1 回あたりの所要時間から見て `XTRANSLATOR_CLIENT_BUDGET`（18 秒）に収まりそうなときだけ行う。
temperature 0 なので同じプロンプトなら同じ出力になり、問題が残った訳もキャッシュする。ログのラベルは `<model> (N problems)` になる。

## 失敗時

- upstream が timeout: 原文をそのまま返す（`finish_reason: length`、ラベル `timeout`）。xTranslator は次へ進む
- upstream が 200 以外: そのステータスと本文を返す
- xTranslator 側の切断（`EPIPE` / `ECONNRESET`）: ログだけ出して続行
  - xTranslator（Delphi REST クライアント）は約 20 秒で切断する。訳は切断後も最後まで作ってキャッシュに入るので、同じ文を再翻訳すれば即座に返る
